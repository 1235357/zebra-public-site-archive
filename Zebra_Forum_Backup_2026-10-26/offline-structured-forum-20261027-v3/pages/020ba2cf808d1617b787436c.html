Like the Big Windows platform - the RFID SDK - on these platforms is of such low demand that alternative methods of interfacing the BT Sled is typically used. Using the "Bluetooth HID" profile on the Bluetooth config for the RFD40_P/P+ && RFD90 - is the safest method of you are doing RFID Data capture.

If you require the ability to update Tags.  - The Mobile (iOS / Android) solution is safer - due to the maturity of the SDK and platforms.

If you feel that you have a sizable MacOS Solution + BT / Wifi connected RFD Sled - envisioned - please contact your Channel / Account teams to investigate a MacOS Pilot - based on a JAVA solution (Likely the faster to implement method for a GUI-Based App.) - or a Linux-Like Native Code that could be run inside of the BREW environment on MacOS for a Command-Line / Service-Like solution.

 

Moving forward for desktop platforms ( Big Windows - Apple Silicon MacOS, Intel Linux, ARM-ish Linux. ) :

Usually for desktop platforms (Windows / Linux / MacOS )- the Fixed Reader RFID solutions, is seen as a more consistent method to interface via an MQTT IOT Broker moving forward.  REST-Based solutions - are an option - but MQTT Broker Services can also be run on these - and an MQTT Client - has cleaner JSON - transactions; compared to HTTP-POST - based solutions.

Also: This does not require a Zebra RFID SDK - rather any MQTT / REST JSON-Based IOT developer solution is suggested.
