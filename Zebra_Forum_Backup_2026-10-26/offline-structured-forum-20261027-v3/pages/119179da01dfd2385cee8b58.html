Hi, Today whilst staging a number of devices I witnessed some unexpected and weird behaviour. Perhaps its my lack of understanding of MSP I dont know but this is what happened. I have a staging bundle that updates the agent on the MC5574, attaches debug30, sets a siteID setting and starts smart staging. What follows is succession of provisioning policies that follow one another.From policy 1 through to 10. This is controlled by an applicability rule in each policy that checks inventory.xxxx exists (from the previous package install) It works very well. During the testing phase I ended up with several terminals in various states of staging which wasnt a problem, I just did a clean boot and blank and started over. I deleted the devices from MSP device status. We started staging from scratch with new devices (never seen before by MSP) and a number of "cleaned" units. The ones that were new followed the policies in order from start to finish. However with the clean devices I noticed that the policies started out of the normal order. Policy number 1 would start as normal but also in parallel policy number 7 would also start. Even when policies 2,3 4,5,6 were not compliant yet. When I checked the package inventory on these devices it showed a package that should not have been loaded yet. This package was not on the device before staging started so MSP must have remembered the device had previously been staged with it. I thought deleting the device from the status screen would clear this sort of information but it didnt appear to. After all it did delete the other packages from the previous install just not this one. A new device previously unknown to this MSP server runs through normally so I know that I'm not adding it in the first bundle. What is deleting the device from status screen doing? Do I need to do a purge somewhere else?

Sean, are you really sure that the application folder on the device was completely wiped and set back to default. Could you check that the folder \application\airbeam\pkg is empty. Any successful installed package on the device stores&nbsp;a package apd file into this folder. If an apd&nbsp;file exists it tells MSP that the package is installed on the device regardless of if the package components are on the device or not. Thomas
