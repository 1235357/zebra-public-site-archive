RFD40 → MQTT: broker shows connected but no tag messages (123RFID on TC22)

T

I am trying to use an RFD40 with MQTT. The MQTT broker shows the client as connected, but I do not receive any tag messages while running inventory in the 123RFID Mobile app.

The RFD40 is paired via Bluetooth to a Zebra TC22 running 123RFID Mobile. In addition, the sled is connected to Wi-Fi and has an MQTT endpoint configured to our broker.

My expectation is that tag reads are published to MQTT while a read operation is active.

Questions:

  1. Does the RFD40 support publishing tag reads directly over MQTT?
  2. If yes, what settings must be enabled, and which topics and payload format should I expect?
  3. If no, can you confirm that a host-side bridge is required and point me to the recommended method for sending tag data to MQTT in this setup?

Hi Tim.

The MQTT does not work in that fashion. If/When an RFID SDK - has control of the NGE on the HH reader - the MQTT if defined can only be available for "Reader Management" functionality and not for RFID expected interactions.

This is very Similar to the FX-Serves Fixed Readers where if an RFID SDK - based Technology is used - the ZIOTC cannot then be used to establish data to/from the RFID NGE on the FX-Series reader.  ( ZIOTC when running - owns the connection to the NGE on-board the FX-Series device.)  At this point the RFD40 / RFD90 Platforms that can do Wifi+MQTT - do not have RFID Capability available.

 

If your RFD40P / RFD40_P+ (Wifi + BT capable + eConnex capable.)  When the Wifi Is defined and has been authenticated (and has a TCP/IP address  config.) then the MQTT can be defined on the HH reader for ( At this time) MQTT MDM remote management:


See this Zebra Doc for details: https://docs.zebra.com/us/en/rfid/rfd4031-uhf-rfid-premium-premium-sled/t-rfd4031-getting-started-with-the-rfd4031/c-rfd4031-wireless-and-connectivity-functionality/r-rfd4031-mobile-device-management-supported-partners.html
