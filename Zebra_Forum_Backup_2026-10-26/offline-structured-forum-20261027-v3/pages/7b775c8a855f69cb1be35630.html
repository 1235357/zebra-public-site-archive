Hello Technical Department at Brain Corporation,

Below are the deep-dive technical guidance, structural differences, and architectural recommendations answering each of your seven core questions.

1. Barcode Symbology Detection and Scanning Without Input Focus 

Developer Query 

Is there an officially supported method for a web application running in a standard Android browser, such as Chrome, to receive barcode data and symbology information without requiring focus on an input field? If this is not supported directly in Chrome, is Enterprise Browser required, or is there another recommended integration method? 

Technical Answer & Analysis 

Standard Google Chrome (Standard Web Browsers): 

  • No, there is no officially supported method. Google Chrome runs within the standard Android application sandbox and does not have native mechanisms to capture or bind low-level Android OS Broadcast Intents directly into a running web page’s JavaScript environment. 
  • The Focus Limitation: When using Chrome, the developer is restricted to using DataWedge’s Keystroke Output plugin. This plugin intercepts the scanned data and inserts it as virtual keyboard strokes. Consequently, a text input field must have active focus for the data to populate, and advanced metadata (like barcode symbology or raw bytes) cannot be programmatically parsed out. 

Zebra Enterprise Browser (EB) Solution: 

  • Yes, fully supported. Enterprise Browser provides the EB Barcode API (EB.Barcode), which exposes the device scanner directly to JavaScript and delivers scan results straight to the web page. 
  • Enabling the scanner: Calling EB.Barcode.enable with a callback activates the scanner. Each time a barcode is scanned (hardware trigger or soft trigger), the callback receives the scan data, including the decoded barcode string (data) and the decoder source and type. 
  • No input focus required: The scan data is returned to the JavaScript callback rather than typed as keystrokes, so the application can write it into any input box (for example by element ID) without that field having focus. 
  • Reference: https://techdocs.zebra.com/enterprise-browser/5-5/api/barcode/ 

JavaScript Sample (Enterprise Browser): 

function onScan(params) { 
    // params.data = decoded barcode string, params.source = decoder/symbology name 
    document.getElementById("barcodeInput").value = params.data; 
    document.getElementById("symbologyInput").value = params.type; 
} 

// Enable the scanner and register the scan callback 
EB.Barcode.enable({}, onScan); 

Recommendation: If standard Chrome must be used, the developer would need to build a custom, lightweight Native Android WebApp Wrapper (using an Android WebView that registers a native Broadcast Receiver and injects scanned data via webView.evaluateJavascript()). Otherwise, Enterprise Browser is the designated and supported out-of-the-box solution. 

2. Controlling Barcode Scanning from On-Screen Buttons 

Developer Query 

What is the recommended implementation method for triggering commands such as START_SCANNING and STOP_SCANNING from JavaScript? What are the differences between Chrome and Enterprise Browser, and are there required settings? 

Technical Answer & Analysis 

  • Google Chrome: Because of security restrictions, standard web pages running in Chrome cannot fire Android system intents. Thus, triggering the scanner via web buttons is not possible in Chrome. 
  • Enterprise Browser: Use the EB Barcode API soft-trigger methods. EB.Barcode.start() performs a soft trigger start (initiates a scan without pressing the hardware trigger) and EB.Barcode.stop() performs a soft trigger stop. Both are available on Android on Zebra devices and are documented at https://techdocs.zebra.com/enterprise-browser/5-5/api/barcode/ 
  • Note: If a scan does not decode, call EB.Barcode.stop() before calling EB.Barcode.start() again. 

JavaScript Implementation Sample (Enterprise Browser): 

 // Scanner must be enabled first; scan results arrive in this callback 
function onScan(params) { 
    document.getElementById("barcodeInput").value = params.data; 
} 
EB.Barcode.enable({}, onScan); 

// On-screen buttons 
function startScan() { EB.Barcode.start(); } 
function stopScan()  { EB.Barcode.stop(); } 
 
// HTML: <button onclick="startScan()">Scan</button> 
//       <button onclick="stopScan()">Stop</button> 

Required Settings: 

  • 1. The scanner must be enabled by calling EB.Barcode.enable before start() is used. 
  • 2. The device must be a Zebra device running Enterprise Browser (the soft-trigger methods are not available in standard browsers). 

3. Physical Key Codes and Key Event Detection 

Developer Query 

Is there documentation listing physical key codes for TC22, TC201, TC501, and are they consistent? Can physical key presses, including scanner trigger buttons, be detected using JavaScript in Chrome vs. Enterprise Browser? 

Technical Answer & Analysis 

  • Key Code Consistency: Yes, key codes are consistent across the TC22, TC201, and TC501 models because they share the unified Zebra Android platform framework: 
  • Left/Right Yellow Scan Triggers: Map to standard Android KeyCode 104 (KEYCODE_BUTTON_L1) or 103 (KEYCODE_BUTTON_R1). 
  • PTT (Push-to-Talk) Button: Maps to KeyCode 228 (KEYCODE_BUTTON_3). 
  • Detection in Web Applications: 
  • Google Chrome: Standard Chrome cannot intercept the hardware scan triggers. The OS intercepts these button events to trigger the active scanner engine via DataWedge, preventing the key events from propagating to the Chrome DOM’s keydown or keyup listeners. 
  • Enterprise Browser: Fully supported via the EB.KeyCapture API, which allows blocking, capturing, and remapping physical key events. 

JavaScript Capture Sample (Enterprise Browser): 

 // Intercept Left Scan Trigger (KeyCode 104) 
EB.KeyCapture.captureKey(false, "104", function(params) { 
    console.log("Hardware Scan Trigger Pressed: " + params.keyValue); 
    // Insert custom business logic here 
}); 

4. Writing Files to Android Internal Storage 

Developer Query 

Which internal storage locations can be accessed using the RhoFile API on Android 13 and later? Are additional permissions required? Is there a method for Chrome, and are there Android version restrictions? 

Technical Answer & Analysis 

  • Scoped Storage Restrictions (Android 11+ / 13+): Zebra devices running Android 13 and later enforce Google’s Scoped Storage guidelines to enhance security. 
  • Access via RhoFile API in Enterprise Browser: Without special permissions, RhoFile can read/write only to the app’s sandboxed private storage: 
  • Private Sandbox: /data/user/0/com.symbol.enterprisebrowser/ 
  • External App Folder: /storage/emulated/0/Android/data/com.symbol.enterprisebrowser/ 
  • Google Chrome Limitations: Standard Chrome cannot write files to arbitrary local directories. A web page in Chrome is restricted to triggering standard web downloads, which the Android download manager places exclusively in the sandboxed /storage/emulated/0/Download/ folder. 

5. Hiding or Disabling the Android Navigation Bar 

Developer Query 

When the Navigation Bar is disabled using StageNow (UiMgr), is it completely hidden to allow full screen use? Are there restrictions on TC22, TC201, and TC501, and how is it restored? 

Technical Answer & Analysis 

  • Visual Behavior: Yes, disabling the navigation bar via Zebra UI Manager (UiMgr) puts the device into a persistent, enterprise-grade Immersive Mode. The navigation bar is completely hidden, allowing the web application to utilize 100% of the screen. System gestures (such as swiping up from the screen bottom) will not temporarily restore the bar if it has been explicitly disabled. 
  • Device / OS Support: Supported across the TC22, TC201, and TC501. When deploying on Android 13 or 14, administrators must use StageNow 5.14+ to ensure compatibility with modern MX security policies. 

  • Restoring the Navigation Bar: To restore the navigation bar, run a StageNow profile with the following UiMgr XML payload: 

    <characteristic type="UiMgr"> 
  <parm name="NavigationBarUsage" value="1"/> <!-- 1 = Enable/Show Navigation Bar --> 
</characteristic> 

https://techdocs.zebra.com/mx/uimgr/#navigation-bar-enabledisable

 

6. Exporting and Importing Device Configurations 

Developer Query 

Is it possible to retrieve existing settings (Wi-Fi, device restrictions, DataWedge profiles) directly from a configured Zebra Android device to apply them to another? Is there a Zebra tool for this? 

Technical Answer & Analysis 

  • Direct Cloning Concept: No, there is no monolithic “clone tool” to pull configuration states directly from one device to copy onto another. Android’s operating system security model restricts apps (including StageNow) from extracting secure properties, credential stores, or database states of other apps. 
  • Zebra-Supported Approach (Configuration-as-Code): Instead of copying from a device, configurations are authored within the StageNow workstation console on an administrative PC and compiled into an XML/barcode deployment profile. 
  • Component-Specific Export/Import: 
  • DataWedge Profiles: Can be exported on-device (DataWedge -> Settings -> Export) as a dwprofile_*.db file. This file can be distributed to other devices via StageNow’s FileMgr and imported programmatically using the DataWedge IMPORT_CONFIG intent API. 
  • Wi-Fi Settings: Securely authored inside StageNow using the WifiMgr CSP and deployed across devices. 

7. Switching Between OCR and Barcode Scanning Within the Same Web Application 

Developer Query 

Is it recommended to use separate DataWedge profiles for OCR and barcode scanning, or modify a single profile dynamically? Can this be controlled via JavaScript in Enterprise Browser? Which devices support OCR, and are there licensing requirements? 

Technical Answer & Analysis 

  • Configuration Strategy: Modifying a single profile dynamically using the SET_CONFIG API is highly recommended over profile switching (SWITCH_TO_PROFILE). Switching profiles triggers a physical unload and reload of the scanning subsystem inside the OS, introducing a ~500ms to 1s delay. Updating configuration parameters dynamically is instantaneous. 
  • JavaScript Implementation (Enterprise Browser): 
  • Switch to Barcode Mode: 
function enableBarcodeScanning() { 
    var config = { 
        "PROFILE_NAME": "YourKioskProfile", 
        "PROFILE_ENABLED": "true", 
        "CONFIG_MODE": "UPDATE", 
        "PLUGIN_CONFIG": { 
            "PLUGIN_NAME": "BARCODE", 
            "RESET_CONFIG": "true", 
            "PARAM_LIST": { "scanner_input_enabled": "true" } 
        } 
    }; 
    sendDWConfig(config); 
} 

  • Switch to OCR Mode: 
function enableOcrScanning() { 
    var config = { 
        "PROFILE_NAME": "YourKioskProfile", 
        "PROFILE_ENABLED": "true", 
        "CONFIG_MODE": "UPDATE", 
        "PLUGIN_CONFIG": { 
            "PLUGIN_NAME": "WORKFLOW", 
            "RESET_CONFIG": "true", 
            "PARAM_LIST": { 
                "workflow_input_enabled": "true", 
                "selected_workflow_group": "OCR" 
            } 
        } 
    }; 
    sendDWConfig(config); 
} 

 function sendDWConfig(config) { 
    EB.Intent.send({ 
        action: "com.symbol.datawedge.api.ACTION", 
        intentType: EB.Intent.BROADCAST, 
        data: { "com.symbol.datawedge.api.SET_CONFIG": config } 
    }); 
} 
  • Device Support & Licensing: 
  • TC501: Fully supports next-generation on-device OCR natively.
  • TC22 and TC201: Support Zebra EdgeOCR via Workflow Input as an optional software-based solution. 

  • Licensing: Standard barcode scanning is free. Advanced OCR pipelines (such as License Plate OCR, VIN OCR, or Identity Document OCR) require a Mobility DNA OCR License per device.
