Manifest Merger Conflict Due to Duplicate Namespace in Zebra RFID SDK AARs

Dear Zebra Technologies Support Team,

I am writing to report a critical issue encountered while integrating the Zebra RFID SDK for Android (API3) into my Android application.

---

Environment Details:
• Device: Zebra RFD40 Premium
• SDK: Zebra RFID SDK for Android (API3) v2.0.5.238
• Gradle Version: gradle-9.2.1-bin.zip
• Android Studio: Latest Stable
• Android Target SDK: Android 14/15

---

Issue Description:

All Zebra SDK AAR files (API3_READER, API3_CMN, API3_INTERFACE, API3_TRANSPORT, etc.) share the same namespace/package name.

In Gradle 9.2.1, a unique namespace is strictly required for each AAR library module. When multiple AARs share the same namespace, it causes a Manifest Merger Conflict at build time, making it impossible to compile the application successfully.

Error observed during build:
• "Manifest merger failed: Attribute application@namespace value conflict"
• "Each library must have a unique namespace"
• Build fails completely — app cannot be compiled

---

Steps to Reproduce:
1. Create a new Android project with Gradle 9.2.1
2. Add the following Zebra RFID SDK AARs to /libs folder:
  - API3_READER.aar
  - API3_CMN.aar
  - API3_INTERFACE.aar
  - API3_TRANSPORT.aar
3. Sync Gradle and attempt to Build
4. Manifest merger conflict error appears immediately

---

Expected Behavior:
Each AAR should have a unique namespace so that Gradle 9.2.1 can successfully merge manifests without conflict.

Actual Behavior:
Build fails due to duplicate namespace across multiple Zebra SDK AAR files.

---

Request:
Kindly provide:
1. An updated SDK build where each AAR has a unique namespace
2. Or a recommended workaround for Gradle 9.2.1 compatibility
3. Official timeline for a fix if a patch is planned

This issue is blocking our development completely. Your prompt response would be greatly appreciated.

Thank you for your support.

Best Regards,
Kalpesh Patel
Kalpesh.patel@sculptsoft.com
