Hello,

We are experiencing a problem when silently upgrading an installed APK through StageNow/MX using Secure Storage Manager and AppMgr.

Environment:

  • Device: Zebra CC600/CC605
  • Android: 14 GMS
  • BSP: 14-41-13.00-UG-U03-STD-HEL-04
  • MX/MXMF: 15.2.0.17
  • Secure Storage Manager: 15.1.0.4
  • SilentAppInstaller: 15.1.0.0
  • Operation: AppMgr Upgrade

Workflow:

  1. FileMgr copies the APK into the recommended SSM destination:

    com.zebra.devicemanager/persist_apk/<application>.apk

  2. SSM successfully stores the file and returns a content:// URI through its FileProvider.
  3. AppMgr passes this URI to SilentAppInstaller for the upgrade.
  4. The upgrade fails with INSTALL_FAILED_INTERNAL_ERROR.

Logcat shows that SilentAppInstaller attempts to open:

/user_de/data/user_de/0/com.zebra.securestoragemanager/cache/persist_apk/<application>.apk

The actual file is located at:

/data/user_de/0/com.zebra.securestoragemanager/cache/persist_apk/<application>.apk

It appears that SilentAppInstaller uses Uri.getPath() as a filesystem path. In the returned content URI, the first user_de is the FileProvider root alias, but it is incorrectly treated as a real filesystem directory. This results in ENOENT / FileNotFoundException.

The same behavior was also observed on an MC3300x running:

  • Android 14 GMS
  • MX 15.0.0.6
  • SilentAppInstaller 14.1.1.0

Using a direct /enterprise/usr/persist/... filesystem path bypasses this particular error, confirming that the APK itself and its signing certificate are valid. However, that approach then invokes an interactive Google Play Protect dialog, so it cannot be used for an unattended upgrade.

Questions:

  1. Is this a known issue in SilentAppInstaller or Device Manager?
  2. Is it fixed in a newer BSP, LifeGuard update, or MX component version?
  3. Is there a supported workaround that preserves the recommended SSM + AppMgr workflow?
  4. Can AppMgr/SilentAppInstaller be configured to open the returned content:// URI through ContentResolver instead of treating Uri.getPath() as a filesystem path?

Thank you.

Mx AppMgr is not able to supress the Google Play messages regardless of whether the APK file is stored via SSM or just copied to /enterprise/usr (which is the easier way to persist the storage of the file). The workaround for this is to disable Play services just before installing the APK and re-enable afterwards - you can do this via Mx AppMgr/idisable app e.g in XML:

   <!--DISABLE-->
   <characteristic version="4.2" type="AppMgr">
   <parm name="Action" value="DisableApplication" />
   <parm name="Package" value="com.android.vending" />
 </characteristic>

 <!--INSTALL APP HERE-->

   <!--ENABLE-->
   <characteristic version="4.2" type="AppMgr">
   <parm name="Action" value="EnableApplication" />
   <parm name="Package" value="com.android.vending" />
 </characteristic>
