Hello Zebra Developer Community,

I am experiencing an issue with the Zebra RFID Android SDK where I intermittently encounter the following error:

 

D/IRFIDinfo(23408): logError RFID_API_LOCK_ACQUIRE_FAILURE LOCK_ACQUIRE_FAILURE in GetAntennaConfig 
D/IRFIDError(31697): RFIDPROTOAscii: GetStatus: RFID_API_COMMAND_TIMEOUTSetAntennaConfiguration size 0 
D/IRFIDinfo(31697): logError RFID_API_COMMAND_TIMEOUT Response timeout

Context:

  • This occurs when changing RFID reader's custom modes frequently, such as switching between a single-tag assignment mode and full inventory mode.
  • The SDK throws a lock acquisition failure when multiple commands are sent to the reader without waiting for the previous operation to complete.

Code Example:
Below is a simplified snippet showing how mode changes are currently handled in Native Android / Kotlin.

"assignmentMode" -> {
    if (reader != null && reader!!.isConnected) {
        lifecycleScope.launch(Dispatchers.IO) {
            try {
                val antennaRfConfig = reader!!.Config.Antennas.getAntennaRfConfig(1)
                antennaRfConfig.setrfModeTableIndex(22)
                antennaRfConfig.transmitPowerIndex = 10
                antennaRfConfig.tari = 18800
                reader?.Actions?.Inventory?.stop()
                reader!!.Config.Antennas.setAntennaRfConfig(1, antennaRfConfig)

                val singulationControl = reader!!.Config.Antennas.getSingulationControl(1)
                singulationControl.session = SESSION.SESSION_S1
                singulationControl.tagPopulation = 1
                val action = singulationControl.Action
                action.setPerformStateAwareSingulationAction(true)
                action.setInventoryState(INVENTORY_STATE.INVENTORY_STATE_A)
                action.setSLFlag(SL_FLAG.SL_ALL)
                reader!!.Config.Antennas.setSingulationControl(1, singulationControl)

                withContext(Dispatchers.Main) {
                    result.success(mapOf("status" to "success", "message" to "Single tag read mode configured"))
                }
            } catch (e: InvalidUsageException) {
                withContext(Dispatchers.Main) { result.error("INVALID_USAGE", e.vendorMessage, null) }
            } catch (e: OperationFailureException) {
                withContext(Dispatchers.Main) { result.error("OPERATION_FAILED", e.vendorMessage, null) }
            }
        }
    } else {
        result.error("READER_NOT_CONNECTED", "Reader not connected", null)
    }
}

"inventoryMode" -> {
    if (reader != null && reader!!.isConnected) {
        lifecycleScope.launch(Dispatchers.IO) {
            try {
                val antennaRfConfig = reader!!.Config.Antennas.getAntennaRfConfig(1)
                antennaRfConfig.setrfModeTableIndex(0)
                antennaRfConfig.tari = 25000
                antennaRfConfig.transmitPowerIndex = getMaxAntennaPower()
                reader?.Actions?.Inventory?.stop()
                reader!!.Config.Antennas.setAntennaRfConfig(1, antennaRfConfig)

                val singulationControl = reader!!.Config.Antennas.getSingulationControl(1)
                singulationControl.session = SESSION.SESSION_S0
                singulationControl.tagPopulation = 30
                val action = singulationControl.Action
                action.setPerformStateAwareSingulationAction(false)
                action.setInventoryState(INVENTORY_STATE.INVENTORY_STATE_AB_FLIP)
                action.setSLFlag(SL_FLAG.SL_ALL)
                reader!!.Config.Antennas.setSingulationControl(1, singulationControl)

                withContext(Dispatchers.Main) {
                    result.success(mapOf("status" to "success", "message" to "Reader restored to normal mode"))
                }
            } catch (e: InvalidUsageException) {
                withContext(Dispatchers.Main) { result.error("INVALID_USAGE", e.vendorMessage, null) }
            } catch (e: OperationFailureException) {
                withContext(Dispatchers.Main) { result.error("OPERATION_FAILED", e.vendorMessage, null) }
            }
        }
    } else {
        result.error("READER_NOT_CONNECTED", "Reader not connected", null)
    }
}

What I Want to Know:

  1. What is the recommended code structure / design pattern for handling all reader-related activities (mode switching, configuration, inventory start/stop) to avoid this LOCK_ACQUIRE_FAILURE?
  2. Are there best practices for queuing or serializing commands in Kotlin/Android when interacting with the Zebra RFID SDK?
  3. Any official guidance or sample code demonstrating safe handling of frequent mode changes and concurrent reader operations?

FYI :  123RFID Mobile app - has a Support Portal here:

https://www.zebra.com/us/en/support-downloads/software/rfid-software/123rfid-mobile.html

The ZIP files found within - have the Android Studio Project and Source Code - which I would recommend as a suggestion to review on the methods that are highly successful. ( If you unpack the ZIP you will find the sideloadable APK as well as nother ZIP file with the Android Studio project and Source Code. The may explain the questions 1,2,3 for the RFID Operations  code.

A quick mention - DO NOT USE 123RFID Mobile app for "Normal" Android Lifecycle RFID app demonstration.
Rather the 123RFID Mobile app is a Demo and Diagnostic app - and the Connection to the RFID HH reader - is "Sticky" and once connected will retain this connection despite the app being put to the Background.

The RFID SDK - for Android Studio - sample code  (HHSampleApp) - does provide the correct "Android Lifecycle" app methods when used with the RFID SDK and RFID Handheld Sleds.
