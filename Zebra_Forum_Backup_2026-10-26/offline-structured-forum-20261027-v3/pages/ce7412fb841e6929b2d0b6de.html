Hi,
quick overview: we are currently running a small logistics web application with multiple customers. There is a button that prints a label with article data. Every customer gets an individual label layout/template. We are using DYMO label printers with their Label Web Print service. This is basically the same thing as Zebra Browser Print: you install the service on your computer with the printer and then you send the print commands from the web frontend via JavaScript to the address+port of the computer to print.

In our current solution, we create the label templates (.label files) in the DYMO label software, put it on the server and let PHP (i.e. Symfony+Twig) replace the placeholders with actual data and send it to the printing API to print the label. All this is done via DYMO's Javascript framework.

Question 1

Now the plan is to migrate to Zebra printers in the future and I am trying to evaluate how it can be done in our application. Since I am new to the Zebra ecosystem, I found it quite hard to find the right keywords to google it myself. But somehow I stumbled upon this thread here:

https://developer.zebra.com/content/creating-zpl-files-nlbl-template-using-net

From what I understand here: we could do it basically the same way as with the DYMO printer.

  1. Design the label with placeholders in Zebra Designer
  2. save it as .prn file, containing ZPL data
  3. put it on the server like the label files before and fill the placeholders with actual data
  4. send the result as ZPL to the Browser Print service to print the label

Would this work?

(note: I don't want to store templates in the printers)

Question 2

The DYMO service has a nifty little feature that creates preview images of labels. That way you can send the XML of the label to the local service and get a base64 encoded PNG back.

Is there something like that available in Browser Print?

Question 2: Is there a label preview API like DYMO’s base64 PNG return?

Unfortunately, Zebra Browser Print does not support label preview generation natively.

However, you have two main options to implement label previews:

Option A: Zebra Designer + PDF Export (Manual)

  • Design the label and export a static image or PDF for preview (e.g., during template creation).
  • This doesn't support dynamic data but can help show layout.

Option B: Use Zebra's Label Preview API (Cloud API – paid)

Zebra has a cloud-based API (called ZebraDesigner Cloud API or Print DNA Label Preview) that can generate PNG previews of ZPL:

  • API Input: ZPL string
  • API Output: Base64-encoded PNG or raw image
  • Docs: Zebra Label Preview API

✅ Pros:

  • Generates preview dynamically with live data
  • Great for user-facing UIs

❌ Cons:

  • Requires Zebra DevConnect account
  • May be paid depending on usage
