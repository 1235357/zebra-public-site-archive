Hi everyone,

I’m running into a strange issue connecting to a Zebra GK420d (ZTC GK420d) printer over USB from an Android app.

On some Android devices, the printer connects and prints perfectly fine. However, on other devices, I consistently get this error when attempting to open the USB connection:

 

E exception in UsbManager.openDevice java.lang.IllegalArgumentException: device /dev/bus/usb/001/006 does not exist or is restricted

Here’s the relevant log output:

 

On Request USB Permissions: (UsbPermissionProvider.java:45)[Binder:2185_8]: Device: UsbDevice[mName=/dev/bus/usb/001/006, mVendorId=2655,mProductId=128,mClass=0,mSubclass=0,mProtocol=0, mManufacturerName=Zebra Technologies,mProductName=ZTC GK420d,mVersion=17.11, mSerialNumberReader=android.hardware.usb.IUsbSerialReader$Stub$Proxy@3079863, mConfigurations=[UsbConfiguration[mId=1,mAttributes=192,mMaxPower=0, mInterfaces=[UsbInterface[mId=0,mClass=7,mSubclass=1,mProtocol=2, mEndpoints=[UsbEndpoint[mAddress=130,mAttributes=2,mMaxPacketSize=64,mInterval=0], UsbEndpoint[mAddress=1,mAttributes=2,mMaxPacketSize=64,mInterval=0]]]]], package: com.forleaf.app (10081), allowed? true 

Even though the permission dialog is accepted and shows allowed? true, the app throws the exception above when calling UsbManager.openDevice().

What I’ve Tried

  • Verified that android.hardware.usb.host is declared in the manifest.
  • Confirmed the app requests and receives permission correctly.
  • Verified the printer works fine on another Android device using the same app build and cable.
  • Tested different USB cables and ports.
  • Reproduced on multiple devices from different manufacturers.

Questions

  1. Are there specific Android permission or SELinux restrictions on certain OEM devices that could cause this?
  2. Does Zebra recommend using a particular USB communication mode (HID vs CDC/ACM) for the GK420d on Android?
  3. Has anyone else encountered the device ... does not exist or is restricted error when using UsbManager.openDevice() with Zebra printers?

Any insight or suggestions would be greatly appreciated.

Hi Pete,

Can you please try the following

  • Add xml file to specify USB devices your application is indented to interact with? e.g., res/xml/device_filter.xml
<?xml version="1.0" encoding="utf-8"?>
<resources>

    <usb-device vendor-id="2655"/>

</resources>
  • Mention this xml in the manifest as meta-data along with USB events
<intent-filter>
    <action android:name="android.hardware.usb.action.USB_DEVICE_ATTACHED" />
</intent-filter>
<meta-data android:name="android.hardware.usb.action.USB_DEVICE_ATTACHED"
                   android:resource="@xml/device_filter" />
  • Request for USB permission - While the intent filter can grant permission automatically upon device attachment if the user allows the app to handle the intent, explicit permission requests may be necessary in some scenarios or if the intent filter isn't working as expected. This is handled programmatically within the application code using UsbManager.requestPermission().
