Discrepancy in Odometer Readings: Clarification Needed on Data Collection Parameters

Hi,

 

We are currently experiencing an issue with odometer reading discrepancies. Our solution retrieves the Odometer.total_label_count value to identify the total number of labels printed per unit. However, when compared with the values provided by the client, the numbers do not match. Please see the images below for reference.

 

Could you help us understand why there is a discrepancy in the values? Is there an explanation for this difference?

 

Value provided by the user

Value used in our platform

Currently, we use the following odometers to collect data:

 

  • odometer.total_print_length
  • odometer.total_label_count

There is a bug in the firmware V75.20.xx for the ZT410 and ZT420 printers. The bug is related to the setting of the display.language SGD. When the display.language is set to English, the readings between the ^HH ZPL command and the odometer.total_label_count SGD are the same. When the display.language is set to Spanish, French, etc., for example, the reading from the ^HH is incorrect. Please use the odometer.total_label_count SGD for the correct reading of the total label count. If you want to get the correct reading from the ^HH, however, the display.language must be set to English. Please note that this issue only happens with the ZT410 and ZT420 printer models.
