                  Hi all,We’re trying to use srfidStartMultiTagsLocationing on iOS to find any of N RFID tags in proximity, and we can’t get the SDK to deliver any proximity callbacks. Single-tag locate (srfidStartTagLocationing) works perfectly on the same setup with the same tags — only multi-tag is broken.Hoping someone with experience on this API can spot what we’re missing.What we observeWhen we call srfidStartMultiTagsLocationing:The call returns SRFID_RESULT_SUCCESS.srfidEventStatusNotify fires with SRFID_EVENT_STATUS_OPERATION_START — so the reader firmware confirms it entered an active operation.The reader physically reads tags and beeps on every tag in range (typical inventory-mode behavior, not locate-mode — beeping continues even when walking away from the registered EPCs).Neither srfidEventMultiProximityNotify nor srfidEventReadNotify delivers a single callback for the reads. Total silence at the delegate level for the entire operation.Multi-tag locate also intermittently crashes the app (no useful stack trace yet — happens deep in SDK frames). Single-tag never crashes.So the reader is reading, the SDK accepts the start, the firmware activates — but reads never bubble up to a delegate method.What we’ve tried (none worked)aRSSIValueLimit — started at 0, changed to -40 per Zebra’s iOS tutorial. No change.reportConfig.setSdkStatusMultipleTagsLocationing(true) vs not calling it — both states produce identical behavior.EPC format — our tags have short EPCs that work fine with single-tag locate. For multi-tag, we tried registering both the raw form (e.g. 00001143) and the 24-char zero-padded form (000000000000000000001143) for each input EPC via addItem:aRSSIValueLimit:. Neither, nor both together, made events fire.EPC normalization — trimmed whitespace, uppercased, deduplicated.Reader profiles — tried FASTEST_READ and DENSE_READ. No effect on multi-tag event delivery.Delegate subscription — confirmed SRFID_EVENT_MASK_MULTI_PROXIMITY is subscribed via srfidSubsribeForEvents:.Same delegate also handles single-tag — srfidEventProximityNotify fires fine during single-tag locate. So the delegate is wired up correctly; only the multi-proximity branch is silent.What we’ve ruled out via process of eliminationReader hardware — beeps on reads, single-tag locate worksBluetooth / transport — single-tag uses the same connectionTag EPC encoding — single-tag locates the same tags fineDelegate registration — proves out via working status notify and single proximityMethod channel / Swift-Obj-C bridging — start call goes through, status notify comes backCode snippet (multi-tag setup)let reportConfig = srfidReportConfig()
for epc in targets {
    reportConfig.addItem(epc, aRSSIValueLimit: -40)
}
let result = api.srfidStartMultiTagsLocationing(
    connectedReaderID!,
    aReportConfig: reportConfig,
    aAccessConfig: nil,                  // ← passing nil here — could this be the problem?
    aStatusMessage: &statusMessage
)
// returns SRFID_RESULT_SUCCESS, then nothing fires in srfidEventMultiProximityNotify
Delegate is implemented on the same class that successfully receives srfidEventStatusNotify, srfidEventProximityNotify (for single-tag), srfidEventReadNotify (for inventory), srfidEventBatteryNotity, etc.QuestionsIs there something obvious missing from our srfidStartMultiTagsLocationing setup? The iOS SDK tutorial example we found omits alloc/init on the srfidReportConfig, so we’re not sure if that example was complete or representative.Should aAccessConfig be a non-nil srfidAccessConfig() instance? The tutorial passes nil but maybe a default-initialized config is required.Are there known compatibility issues between iOS SDK v1.1.94 and RFD40 firmware for multi-tag locate specifically?Is there a way to enable verbose SDK debug logging on iOS so we can see the internal ECRT: log lines (we can see strings like ECRT: software filter epc=%@, limit=%d in the framework binary, suggesting internal debug logs exist)?The Zebra Android docs show multi-tag locate firing through eventReadNotify with getMultiTagLocateTagInfo(). Should iOS multi-tag also fire through srfidEventReadNotify (which we also tried — never fires during the locate either)?A recent forum thread (Best approach for GTIN-based tag locating with dynamic tag switching) suggested srfidStartTagLocationing with an aTagEpcMask is a recommended alternative. Is that the official guidance for “find any of N similar tags” on iOS, with multi-tag-locate considered legacy?EnvironmentReader: Zebra RFD40iOS RFID SDK: v1.1.94iOS: 17.xTag encoding: ours are short-form EPCs (e.g. 8 hex chars / 32 bits as reported by the reader during pair operation)Single-tag locate confirmed working with the same tags and same readerThanks for any pointers — happy to provide additional logs or test specific configurations.
