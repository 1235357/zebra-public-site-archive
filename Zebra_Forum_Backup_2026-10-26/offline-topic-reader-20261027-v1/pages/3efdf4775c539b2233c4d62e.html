                  For some time now, I have noticed issues with Zebra Setup Utilities(ZSU) when changing the Bluetooth name of ZQ320 Plus printers. In ZSU, the following command is executed under "Open Communication With Printer": ! U1 setvar "bluetooth.friendly_name" "Testing" "ZDesigner ZQ320 Plus (CPCL)" was previously selected from the printer list.After clicking "Send To Printer," ZSU usually stops responding and has to be closed and reopened. In instances where ZSU does remain responsive after the set command, the command ! U1 getvar "bluetooth.friendly_name" yields no output, and ZSU subsequently stops responding. However, if ZSU is restarted and the Bluetooth name is checked using the get command, the change has actually taken place. This error also occurs with the current version v1.1.9.1327 of ZSU.Is this behavior known, and is there a solution for it?

            As a Bluetooth SME - and when I configure Anything BT on Mobile printers - I follow the S-G-D - with the last command being "device.reset" as seen as follows:

<snip>
! U1 setvar "bluetooth.enable" "on"
! U1 setvar "bluetooth.friendly_name" "PRNZQ320_1"
! U1 setvar "bluetooth.discoverable" "on"
! U1 setvar "bluetooth.minimum_security_mode" "1"
! U1 setvar "bluetooth.bluetooth_pin" "1234"
! U1 setvar "bluetooth.bonding" "off"
! U1 setvar "bluetooth.enable_reconnect" "off"
! U1 do "device.reset" ""

</snip>

// Note the extra "entered" blank line after the last command in the Cut'n Past Above...

I hope this may help you - NOTE - when the printer restarts - you will need to close comms with the Printer (If using ZSU on Windows) and re-open the printer once it is back online and available to the USB staging / config connection.
