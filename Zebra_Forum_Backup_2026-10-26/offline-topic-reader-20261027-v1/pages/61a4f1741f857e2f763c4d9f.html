            Without seeing the code, we cannot be sure about the cause of the issue. In general, we should keep in mind that we don't overflow the Bluetooth buffer by transmitting a large amount of data in one shot. Secondly, we don't want to overflow the receiving buffer on the printer. The recommended workflow is to check the printer status before sending data to the printer.

Open a connection
Check the printer status to see if it's ready.
If the printer is ready to print, then send the print data to the printer to print. If the printer is not ready, the wait for sometime and check the status again.
Check the printer status again, before we close the connection. We don't want to close the Bluetooth connection prematurely, as there could be some un-transmitted data in the Bluetooth buffer waiting to be transmitted.

Please note, by default, there is a 5 sec delay when calling the connection.close() API in the SDK on a Bluetooth connection on Android.
