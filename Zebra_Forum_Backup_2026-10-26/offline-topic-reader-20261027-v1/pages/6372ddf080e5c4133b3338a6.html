                  The Request:Zebra OEM Info API can read the touch mode property.but the following property didn't update after user change the touch mode.we need a new OEM Info API to allow app developer to force update the variable system properties like:- persist.sys.touch_mode- persist.vendor.sys.touch_modehttps://techdocs.zebra.com/oeminfo/consume/USE CASE:customer want to integrate "control panel touch mode" feature inside their appthey successfully implemented the feature to set touch mode by submit xml file to EMDK profile processor, and they can persist a touch mode status inside their app.[Working Scenario] app boot > read current selected touch mode and save to app internal status > change app internal status while user select the mode > rendering current mode on UI.[Problem Scenario] app boot > read current selected touch mode and save to app internal status > user jump to android setting page directly change touch mode > wrong status rendering on UI.

            This request highlights a practical gap in Zebra’s OEM Info API. While reading the touch mode works, the lack of real-time synchronization creates inconsistencies when users change settings outside the app. Providing a method to refresh or force-update system properties like persist.sys.touch_mode would improve reliability and user experience. It would also help developers maintain accurate UI states without relying on indirect workarounds or repeated app restarts.
