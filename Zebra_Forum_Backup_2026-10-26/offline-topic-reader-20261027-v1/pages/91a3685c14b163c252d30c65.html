            I have a similar issue with an Android 8.1 MC333R with the same error message.  After investigating, what I've found is that the Context becomes null in API3Utils.isDeviceRFID() during the reflection-based TransportSerial instantiation.More info:# Final Diagnosis: Zebra SDK Bug## Confirmed IssueBased on the logs, we can definitively confirm:1. ✅ `Android.App.Application.Context` returns `MainApplication` correctly2. ✅ The context is the same object as `this` in `MainApplication.OnCreate()`3. ✅ We're passing the correct context to the SDK4. ✅ The `Readers` object is created successfully5. ❌ **BUT** when `GetAvailableRFIDReaderList()` calls `TransportSerial.<init>()` via reflection, the context becomes null## The Root CauseThe Zebra RFID API3 SDK version **2.0.5.226** has a bug in `API3Utils.isDeviceRFID()` where it tries to access a context that wasn't properly stored during the reflection-based instantiation of `TransportSerial`.### The Problematic Code Path```Readers.GetAvailableRFIDReaderList() → Readers.loadSerialDevices()   → new RFIDReader()  // Uses reflection     → Constructor.newInstance0()       → TransportSerial.<init>()         → API3Utils.isDeviceRFID()           → context.getSystemService() // ← context is NULL here!```The context is lost during the reflection-based construction.## Why This Happens with MAUIThe SDK likely has internal assumptions about:1. How the Application class is structured2. How contexts are stored/retrieved across the JNI boundary3. Thread-local storage or static context holders.NET MAUI's `MauiApplication` base class may interfere with these assumptions.## What We Tried (All Failed)1. ❌ Timing delays (2s + 2s + retries)2. ❌ Activity Context vs Application Context3. ❌ Garbage collection prevention4. ❌ Static context storage5. ❌ Forced GC before SDK calls6. ❌ Context validation7. ❌ Multiple retry attempts**None of these worked** because the issue is inside the SDK's native code, not our code.## The Evidence### Log Proof```SDK will receive context type: MainApplicationSDK context equals MainApplication: TrueCreating Readers object with ServiceSerial transport...Readers object created successfully  ← SDK received context!Getting AvailableRFIDReaderList...RuntimeException during ServiceSerial initialization: Inner exception: Attempt to invoke virtual method 'java.lang.Object  android.content.Context.getSystemService(java.lang.String)'  on a null object reference  ← But context is null HERE!```### Stack Trace Proof```at com.zebra.rfid.api3.TransportSerial.<init> at java.lang.reflect.Constructor.newInstance0(Native Method)  ← Reflection loses context at java.lang.reflect.Constructor.newInstance at com.zebra.rfid.api3.API3TransportWrapper.initTransport```## ConclusionThis is **definitively** a Zebra SDK bug, not an issue with your code or configuration. The SDK's reflection-based instantiation of `TransportSerial` loses the context reference when called from .NET MAUI applications.**You need Zebra's help to resolve this.**---**Status**: Issue diagnosed ✅  **Root Cause**: Zebra SDK bug ✅
