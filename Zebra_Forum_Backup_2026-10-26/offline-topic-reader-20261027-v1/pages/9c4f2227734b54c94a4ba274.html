                  Hello, I have a problem with text wrap in field blocks created with ZPL command ^FB. The block is made up of 17 lines, left justified. Each line has the escape sequence \& to go to a new line when needed, and everithings work fine when line are shorter than the label. The problem comes when a line is longer and automatically wrap to a new line: if the has some spaces between words (see example line 5 in the image attached) it works fine, the subsequent line start in a new line, when there are no spaces (see example line 8) it automatically wrap with an added "-" but the next line start on the same line, not on a new line, the "\&" is ignored.Someone have a solution?

            To make the \& work as a carriage return and new line feed in the ^FD statement, you would need to have a preceding ^FB statement to define a box, so that the printer knows where the next line should start. Without the ^FB, everything in the ^FD will be in one line. In ZPL there is no command to breakup the text you want to write based on its length. You have to break it into 2 or 3 variables as per the length and then you can write it using that 2 or more ^FD commands.
See the examples of multi lines in a text block in the ^FB section in the ZPL User Guide. You can use this link for preview of output from your ZPL code https://labelary.com/viewer.html
