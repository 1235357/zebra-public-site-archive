                  We are encountering a critical issue when connecting to a Zebra ZD621D printer over Bluetooth Low Energy (BLE) using the Zebra Android SDK (ZSDK_ANDROID_BTLE.jar v2.16.5518) on certain Android 12 (API 31) devices, and we have reproduced the problem using the official Link‑OS Multiplatform SDK demo application. The SDK consistently fails with the error “Error writing to connection: Bluetooth LE Write timed out”, thrown when calling printer = ZebraPrinterFactory.getInstance(printerConnection);. Despite this failure, our extensive testing confirms that the BLE GATT layer is fully functional: BluetoothLeConnection.open() succeeds, service discovery completes with status 0, the MTU increases successfully to 247 bytes, isConnected() returns true, and no GATT errors or disconnections occur. Crucially, when we bypass the Zebra SDK and write directly using the native Android BluetoothGatt.writeCharacteristic() API on the same active GATT connection, the writes complete successfully and trigger the expected onCharacteristicWrite() callback. This clearly indicates that the BLE link is stable, the printer accepts writes, and the issue lies specifically within the Zebra SDK’s internal BLE write implementation. Has anyone experienced a similar issue or found a solution or workaround?
