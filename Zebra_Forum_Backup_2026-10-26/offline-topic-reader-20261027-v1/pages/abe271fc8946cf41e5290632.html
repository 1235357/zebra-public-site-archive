                  srfidStartMultiTagsLocationing returns SUCCESS but no proximity events fire on RFD40 / iOSsrfidStartMultiTagsLocationing accepts our start call and the reader runs, but the SDK never delivers a single callback. Single-tag locate (srfidStartTagLocationing) works perfectly with the same tags on the same reader.Observed sequencesrfidStartMultiTagsLocationing returns SRFID_RESULT_SUCCESS.srfidEventStatusNotify fires SRFID_EVENT_STATUS_OPERATION_START.Reader beeps continuously on every tag in range — inventory-mode behavior, beeping continues when walking away from the registered EPCs.Neither srfidEventMultiProximityNotify nor srfidEventReadNotify fires during the locate.App also crashes intermittently — only on the multi-tag path, never on single-tag.Setuplet reportConfig = srfidReportConfig()
for epc in targets {
    reportConfig.addItem(epc, aRSSIValueLimit: -40)
}
let result = api.srfidStartMultiTagsLocationing(
    connectedReaderID!,
    aReportConfig: reportConfig,
    aAccessConfig: nil,
    aStatusMessage: &statusMessage
)
SRFID_EVENT_MASK_MULTI_PROXIMITY is subscribed. Same delegate class receives srfidEventStatusNotify, single-tag srfidEventProximityNotify, srfidEventReadNotify (during inventory) — only the multi-proximity branch is silent.Tried, none made events fireaRSSIValueLimit at 0 and at -40 (per iOS tutorial)setSdkStatusMultipleTagsLocationing(true) and not calling itEPC pattern: raw short form (e.g. 00001143), 24-char zero-padded form, both registered together, uppercased / trimmedReader profiles: FASTEST_READ, DENSE_READQuestionsIs aAccessConfig: nil correct, or does multi-tag require a non-nil srfidAccessConfig()?The iOS tutorial example omits alloc/init on the srfidReportConfig — is that example complete?Known iOS SDK v1.1.94 vs RFD40 firmware compatibility issues for multi-tag locate?Any way to enable verbose SDK logging? The framework binary contains debug strings like ECRT: software filter epc=%@, limit=%d — would be useful to see them.Android docs show multi-tag firing through eventReadNotify. Should iOS multi-tag also surface there, or strictly through srfidEventMultiProximityNotify?The recent thread “Best approach for GTIN-based tag locating with dynamic tag switching” suggests srfidStartTagLocationing with aTagEpcMask for find-any-of-N. Is multi-tag-locate considered legacy on iOS?EnvironmentReader: Zebra RFD40iOS RFID SDK: v1.1.94Tag encoding: short-form EPCs (8 hex chars / 32 bits as reported by the reader)Single-tag locate works on the same tags / same readerThanks — happy to share more logs or test specific suggestions.

            FYI - for any iOS RFID SDK questions - I prefer to validate certain functionality operates on the Apple Store released version of 123RFID Mobile app.As a result of which - the Multi-Tag locate - typically is done via the Demo Config setting for "Application Menu" - of "Export Data"  slider activated.For any Inventory (trigger pull / then trigger release) - this will then save the Inventory Captured data to a flat file to the iOS filesystem (Save to files) button.{ Mine saves to the "Download" folder in the file dialog. }  [ Quick Tip activate this feature 1 time take an inventory and Save it, and then turn the "Export data" off. ]When you goto "Locate Tag" in the main screen UI - the Locate Tag featue has "Single Tag" locate - which is whatever highlighted "inventory" view EPC you selected.ORMulti Tag locate <tab>  - that if you click the lower RH corner icon of a sheet of paper with a (+) in the icon. ( Recents alas is the default starting point, navigate to "Browse" in the bottom right, and choose the up-to-date "TagList########" file.If you choose the correct "Export file" - the screen / UI when it returns will show the "INVENTORY SUMMARY" list of the tags you exported. <quick point> on Android ( RFID SDK for Android Studio 123RFID Mobile ) this export file should do the Multi-Tag locate and show status's - However, On iOS this currently seems to fail on V1.1.94.
