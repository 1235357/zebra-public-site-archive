                  Hi all,I've completed several projects with this controller family, all in production progress-tracking contexts, with RFID read cycles coordinated by electrical signals or software triggers. I'll soon be starting new projects involving classic RFID read portals for automatic detection of passing packages/cartons. I was wondering whether, besides the portal activation strategy based on photocells, I could consider keeping the controllers always in "start" mode — i.e., with read mode always active. Has anyone had experience with this on FX controllers? Are they stable, or are there any issues when kept in continuous read mode all the time?Obviously a strategy like this could greatly simplify the implementation scenario — do you see any downsides to it?The setup will use the usual IoTConnector + MQTT configuration.Best regards,Franco.

            Hey, Physically there is no issue to stay in reading mode continuously.Probably not good approach for all use cases and not very green;-)I have a few implementations where we are in inventory mode with interval 0, which will allow the reader to report all the reads.I also have used and recommend simple mode which will basically only report a tag read the first time it is in "field of view" or specific antenna view.hope this helps!

            Hi Alex, thanks for your input, and sorry for the delay — I was on vacation. I agree with your point that not all scenarios are suited to continuous reading mode. I was considering it as a way to simplify certain installations where using photocells or other activation triggers is difficult.Regarding your recommendation on using "simple mode," I have just one doubt about it. Based on my experience, I've always favored read strategies that give me, where possible, a minimum baseline of repeated reads per single tag. This allows me, during data analysis, to make more in-depth considerations about the detected tags. Where not dictated by specific conditions, isn't relying on a single-read approach somewhat limiting?
