                  Hello,We are using Zebra Link-OS iOS SDK with a Zebra ZD621 printer over MFi Bluetooth.Use case:Our app generates multiple badge images first, then prints them one by one using GraphicsUtil printImage.Current code flow:self.connection = [[MfiBtPrinterConnection alloc] initWithSerialNumber:serialNumber];[self.connection open];if ([self.connection isConnected]){   self.printer = [ZebraPrinterFactory getInstance:self.connection error:&connectionError];   id<GraphicsUtil, NSObject> graphicsUtil = [self.printer getGraphicsUtil];   for (UIImage *image in arrAllPrints)   {       NSError *error = nil;       BOOL success = [graphicsUtil printImage:[image CGImage]                                           atX:x                                           atY:y                                     withWidth:width                                    withHeight:height                             andIsInsideFormat:NO                                         error:&error];       if (!success)           break;   }}Problem:When printing multiple badges, only the first badge physically prints on the Zebra ZD621.             Hi Mog,The SDK is functioning as designed. The tight for loop in your code sends heavy image data too fast, overflowing the printer's receive buffer.
1. Recommended way: Move your print loop to a background thread to prevent UI freezing. Send one image, pause and poll the status, and only proceed to the next iteration when the printer is ready.2. Return timing: printImage returns immediately once data enters the iOS buffer, not after the physical print/cut.3. Required polling: Yes. After each print in your loop, poll PrinterStatus and wait until numberOfFormatsInReceiveBuffer == 0 and isReadyToPrint == true before sending the next image.
Refer this documentation for more details: https://techdocs.zebra.com/link-os/latest/ios/If you face further issues, you can submit a support case through the Zebra Support Center here: https://support.zebra.com/
