                                        Overview

Zebra Identity Guardian is a software solution designed to streamline authentication strategies and provide secure, seamless, and personalized user access to enterprise mobile devices. By merging facial biometric authentication with multifactor login protocols, it balances convenience with robust security. Identity Guardian integrates with identity providers (IdPs) for Single Sign-On (SSO) and offers specialized configurations for two primary deployment use cases: Shared Devices and Personally Assigned Devices.

Key benefits:


User Data Protection - Multiple layers of protection ensure that employee data is protected, while employees have control over their data.

Application Authentication - Integration with identity providers (IdPs) simplifies authentication by only requiring users to log in once and then leveraging single sign-on (SSO) to streamlines the process.

Facial Biometrics - Users seamlessly and securely unlock their mobile device using facial biometrics.

Multifactor Login - For enhanced security, users can be prompted to provide multiple authentication factors to sign into a device: facial recognition, user passcode, and/or SSO authentication

Accountability - Empowers administrators with comprehensive visibility into devices and their associated users.

Personalization - Enables organizations to customize on-device experiences that are specifically tailored to align with the roles of the users.




Main Features

Identity Guardian main features:


Supports user enrollment and authentication for shared and personally-assigned devices

Multi-factor authentication support:



Unique user barcode authentication

Facial biometric authentication

NFC card authentication

User passcode authentication

SSO authentication using Microsoft Entra ID or PingID


Supports other apps and device events that invoke the lock screen

Installation and configuration can be performed through Zebra DNA Cloud

Device usage details and user information is visible from the Zebra DNA Cloud console




Usage Notes


IMPORTANT: Screen lock in Android device settings must be set to “None.” Other types of screen locks, such as swipe or pin, are not supported.

A Verification Setup must be selected for Shared Device Authentication > Lock-screen Event Options > On device manual checkin. Setting this parameter to NONE is not supported. 

While performing facial biometric authentication on a Zebra ET45, the device must not be rotated.

Automated Security Enhancements:



Automatic Barcode/NFC Expiration: Enforces configurable expiration periods on enrollments requiring barcode or NFC card authentication, automatically restricting expired profiles and prompting re-enrollment to ensure credentials remain up to date.

Account Lockout (Passcode): Automatically locks accounts for a predefined duration after exceeding allowable failed passcode attempts, mitigating brute-force risks.


New Quick Access (Apps) allows device users to open approved non-sensitive utility applications directly from the Identity Guardian lock screen without requiring prior authentication.

New MPIN-Protected Guardian Safe - Secures credentials and personalized settings on Shared Devices using a Master Personal Identification Number (MPIN), enabling profile access across multiple sessions and devices without replacing administrator-configured authentication factors.

New Personalized Device Settings: Grants authenticated users access to specified Android system settings, allowing individual customization of key display, audio, and accessibility preferences tailored to the needs of their active sessions.

Support for Wearable Computers: Delivers an optimized, compact interface for streamlined multi-factor authentication on devices such as WS301 and WS501.

Known Issues

Facial Biometrics & Enrollment:


When the device camera is facing a TV playing a video, users may experience difficulties capturing facial biometrics for enrollment and authentication. Zebra recommends capturing facial biometrics in a well-lit environment for optimal results.

If the user's face is not fully positioned within the guided circular view, they may encounter issues capturing facial biometrics during enrollment. Zebra recommends ensuring that the entire face is within the guided circular view for successful biometric capture.

Teams Auto-Sign-In Interrupted on Rapid Re-Enrollment: If the enrollment process is exited immediately after signing into Microsoft Teams, and a new enrollment session is started right away, the Teams auto-sign-in mechanism for the new user may fail to complete immediately. While the new user sign-in will eventually start when sharing a barcode from the Print screen, the barcode may need to be shared a second time once the sign-in process fully resolves. To avoid this issue, Zebra recommends waiting approximately 5 seconds on the lock screen before tapping Enroll User again to allow the background sign-out process to complete.


Guardian Safe & Auto-Fill


After upgrading to Identity Guardian 2.1, the Guardian Safe and Auto-Fill SSO Login features may not function as expected. To resolve this, Zebra recommends logging out and logging back in, then re-enabling both features.

The Guardian Safe button may not function or may intermittently disappear on the login screen of certain native apps. However, users can still access the Guardian Safe app directly to edit and manage their passwords.

Users may experience a brief delay in password autofill when using the "Auto Fill for SSO" or "Guardian Safe" features, particularly after a device reboot or when the device wakes from a low-power state (doze mode). To minimize this impact, allow a few seconds after the device restarts or wakes up before attempting to log in.

Guardian Safe Overlaps Keyboard: To prevent the blue Guardian Safe icon from blocking the keyboard, tap the > character to minimize it.


Guardian Safe and Auto-Fill SSO supports only a single device per user ID for Personally Assigned Devices. Registering multiple devices with the same user ID causes undefined behavior.

FLAG_SECURE Limitation (Android 14+): Guardian Safe does not auto-fill credentials for applications using the FLAG_SECURE window flag on Android 14 or higher. Manual credential entry is required for affected applications. On Android 13 and lower, Guardian Safe functions normally.


Blocking Screen/Lock Screen Behavior:


Users are unable to answer a call from the notification bar if the Identity Guardian blocking screen is in the foreground, even if the application is in the allowed list to appear over the blocking screen. Ensure the Identity Guardian blocking screen is not active in the foreground when attempting to answer a call from the notification bar.

After adding the Identity Guardian package name under “Apps Allowed on Lock Screen,” users cannot access the Guardian Safe app list on the device.

Lock Screen Unresponsive with Allowlisted Apps and Keyguard: When Keyguard is enabled, the Identity Guardian lock screen may prevent a user from logging in if an allowlisted app (like the phone) is active when the device resumes from suspend. To recover, the user must suspend and resume the device one more time.

Brief Android Keyguard Exposure After Reboot: In Personally-Assigned Device mode with Identity Guardian registered as the Keyguard and FACE as the primary authentication factor, swiping up on the first suspend/resume cycle after a reboot may briefly display the default Android keyguard (~1 second). Note: This is a visual anomaly only; users cannot input a PIN, pattern, or passcode during this transition.

Apps Allowed on Lock Screen Limitation with ZDNA: Zebra DNA supports a maximum of 10 entries for Managed Configuration bundle arrays. This affects Identity Guardian managed configurations, such as Apps Allowed on Lock Screen. If listing multiple activities for a single app package, use a wildcard * for the activity name to remain within this limit.


Single Sign-On & Authentication Flow:


When using Microsoft Entra ID for single sign-on (SSO), a new user is not automatically logged into Microsoft Associated apps following the sign out of a previous user. To address this, users can either relaunch the Microsoft Associate apps or enter the newly logged in user ID when prompted, ensuring a successful login.

Microsoft Teams Auto-Sign-In Issue During User Switch: When switching users on a shared device where the primary user has logged in via SSO and opened Teams (which auto-signs them in), suspending and resuming the device disrupts the auto-sign-in mechanism for the subsequent session. When a secondary user enrolls on the device through the lock screen, authenticates via SSO, and selects Teams from the application selection screen to share their barcode, they are prompted with a manual login screen instead of being automatically signed in. Workaround: Tap the device's back button to return to the application selection screen, then tap the Teams button again to trigger the auto-sign-in.

A user authentication error might occur intermittently if a user attempts to cancel SSO authentication and then tries to re-authenticate. To resolve this, click on any button on the error screen to dismiss the error, allowing the user to proceed further.

SSO Temporary ID Persistence: When upgrading Identity Guardian with SSO Temp ID enabled, previously created Temporary IDs do not persist across the upgrade cycle and cannot be retrieved. The user must generate a new Temporary ID again.

Camera Fails After Cancellation: On WS301, WS501, and ET401 devices equipped with camera-scanners and configured for both Barcode and Face Authentication, canceling Face Authentication and subsequently attempting to scan a barcode prevents the camera from launching.Recovery: On ET401, suspend and resume the device to restore camera functionality. On WS301 and WS501, perform an Admin Bypass login/logout or execute a full device reboot to restore camera functionality.

Authentication Method Update Discrepancy: During transitions from SSO-based re-enrollment to One-Time PIN authentication within an existing profile, device updates may fail to register. Consequently, selecting "Re-enroll" on the device triggers the original SSO prompt rather than the intended One-Time PIN verification screen.
Workaround: Ensure the correct authentication method is applied by fully removing the existing profile from the target device. Once removed, deploy the newly configured profile. A standard profile overwrite (re-application) is insufficient.

Passcode Screen UI: On the passcode authentication screen, entering an incorrect passcode displays an error message that shifts the layout, causing the keypad to partially obscure the bottom action button.
Impact/Workaround: The visible portion of the action button remains functional and responsive to touch input.



EMM, Launcher, & Third-Party Integrations:


Devices configured with SOTI Kiosk Mode may intermittently encounter an authentication error when logging in with SSO credentials after a reboot. To avoid this issue, Zebra recommends to wait at least one minute after rebooting the device before attempting to log in with SSO credentials.

On ET401 devices running Android 15, Imprivata's Mobile Device Access is unable to allow all required permissions, preventing Identity Guardian configuration and lock screen setup.

Post-Reboot Identity Guardian Sequence Issue: When a device reboots after a Workspace ONE logout, the Identity Guardian lock screen displays after the Workspace ONE Launcher login screen instead of preceding it.

The behavior of Guardian Safe may vary depending on the version of Workspace ONE launcher in use. If any discrepancies are observed, please contact Zebra Support.

Identity Guardian may become temporarily unresponsive after Workspace ONE Intelligent Hub update. To recover, tap Wait on the system prompt. Identity Guardian should resume once the Hub service becomes available. If it does not recover, reboot the device. This is a temporary condition and does not block the user permanently.




Version History

New in 3.1


New Brute-Force Protection: A tiered device security mechanism that deters unauthorized access by enforcing progressive, customizable login delays while providing an admin bypass option for immediate lockout resolution.

New Keyboard Input Configuration: Administrators can now streamline the user sign-in experience by configuring a specific Alphanumeric or Numeric-only keyboard layout for all authentication screens.

Unlock via NFC/Barcode: Streamline workflows on shared devices by allowing users to instantly resume an active, locked session with a simple NFC tap or barcode scan, bypassing the need for full re-authentication.

New Launch Apps to Share Enrollment Barcode: Streamline the self-enrollment workflow by pre-authenticating SSO-enabled applications (Microsoft Teams and Outlook) to ensure seamless, one-step barcode sharing without login interruptions.

New Default SSO Domain Configuration: Streamline Microsoft Entra ID authentication by allowing users to log in using only their username while the system automatically applies the pre-configured domain.

A Managed Configuration setting for Guardian Safe has been renamed from "Guardian Safe" to "Append Username and Password Safe."

Updated instructions for Generate Enrollment & Authentication Key.


New in 3.0


Device Mode Distinctions (Shared and Personal Device) and Keyguard Updates: Introduced significant enhancements to the configuration workflow, primarily focused on creating a clear distinction between Shared Device and Personal Device management.



The "Launch IG lockscreen from Keyguard" option has been removed from Lock Screen Configuration and replaced by the "Keyguard" option under Usage Mode.

In Managed Configurations, "Authentication Configuration" has been renamed to Shared Device Authentication to clarify its scope.

A new, separate Personal Device Authentication section is added to Managed Configurations.

The "DEVICE STORAGE" option has been removed from Comparison Source under Shared Device Authentication, as Personal Device Authentication is now separated into its own dedicated section.

Various related titles and descriptions have been refined for greater clarity in Managed Configurations.

Instructions within the Unified Lock Screen (Keyguard) guide are now separated into distinct steps for Shared Devices and Personal Devices.

The Get Current User Session API documentation now includes sample output for various Personal Devices scenarios.

Provided detailed information regarding backwards compatibility for configurations that used the legacy "Launch IG lockscreen from Keyguard" option on Personal Devices.


Administrators can now gain more insight into user activity through the new capability to view device user login history via Zebra DNA Cloud.

Imprivata State Broadcast: Identity Guardian now acts as a bridge to broadcast Imprivata login state changes through Proxy Mode, allowing registered applications to seamlessly retrieve user details during sign-in and sign-out via the Get Current User Session API.

Enhances facial biometrics with improved face recognition capabilities, due to the updated Biometrics SDK used by Identity Guardian.

Updated Minimum NFC Card Capacity: Added a new requirement for NFC cards; a minimum capacity of 2 KB is required to successfully store user enrollment data.

The default value for Liveness Threshold (under Facial Authentication Configuration) is now "Low." Previously, the default value was "Medium/High".

New Workspace ONE Logout Configuration: To ensure a seamless logout experience, a new custom XML configuration is now required in VMWare Workspace ONE UEM. This allows Identity Guardian to operate successfully upon logging out from the Workspace ONE UEM launcher. This update also resolves the intermittent screen alternation issue detailed in the Resolved Issues section below.

Resolved Issues:



Screen Flashing in Desktop Mode After Reboot: Fixed an issue where the device screen would flash after rebooting while docked and connected to a secondary display. This previously occurred when the device was configured for "Desktop Mode" via MX Display Manager with the lock screen set to "Swipe."

Resolved an intermittent issue where rebooting a device and attempting to unlock it using the "Scan to Unlock" button with PingID resulted in an "SSO Session Timeout Error." This fix also addresses instances where an SSO Sign-out page was displayed instead of the expected Identity Guardian lock screen after a reboot.

Fixed an issue where active Okta sessions persisted in Identity Guardian across user switches when a new user signed in via 'Switch User' using a non-SSO method. Now, the previous user's SSO session in Identity Guardian is automatically terminated. Note that Identity Guardian does not terminate the previous user's active Okta sessions in other applications.

Resolved a compatibility limitation, ensuring Guardian Safe and Auto-Fill SSO Login now function correctly alongside Alternative Login configurations.

Resolved an issue in environments configured for SSO-exclusive login where a password-save popup appeared unexpectedly, even when Guardian Safe and Auto-Fill SSO Login were not utilized.

Corrected a behavior in the zDNA Cloud dashboard where a stale error message persisted after an initial Keyguard deployment failed due to missing requirements.

Workspace ONE Logout Screen Alternation (Configuration Required): Resolved an intermittent issue where screens would rapidly alternate between Workspace ONE and Identity Guardian during the logout process. To apply this fix and allow Identity Guardian to operate correctly upon logout, the new custom XML configuration must be implemented in VMWare Workspace ONE UEM.



New in 2.9


The maximum Storage Period for user authentication data is now 14 hours, an increase of 2 hours, providing more flexibility for authenticated sessions.

Suppress Camera Preview During Face Authentication - For increased privacy, administrators can now hide the camera preview during face authentication. Users are guided by a simple status icon instead of a live video feed:



🟢 Green smiley face: Face is properly aligned.

🟡 Yellow neutral face: Camera reposition is needed.


The response from the Lock Screen Status API now includes a timestamp, enhancing the ability to monitor lock screen state changes over time.

Login Enhancements: New enhancements improve login speed, reliability, and the overall user experience while maintaining strong security standards. These updates ensure seamless application access, even in limited connectivity scenarios. Key highlights:



Faster Re-login: Streamlines the re-login process by eliminating repeated server validation during active sessions, which reduces login time and improves efficiency.

Offline Login Support: Permits login during temporary offline states if the session remains active. This ensures uninterrupted access in areas with low or no network connectivity.

Enhanced Performance: Minimizes dependency on backend services for a faster and more responsive login experience.

Automatic Logout on User Status Change: If a user account is deleted or expires in the zDNA admin portal, the system automatically logs out the user from the device to maintain security compliance.


Google Play Updates are disabled by default starting with April 2026 LifeGuard Updates, improving device staging reliability.

Automated Logout Synchronization with EMM: Adds the On User Logout From EMM option to Managed Configurations for synchronizing EMM and Identity Guardian user logout sessions. Enabling this setting ensures that terminating an EMM session triggers an automatic logout from Identity Guardian. The Identity Guardian lock screen then appears over the EMM login interface, maintaining device security and providing a seamless transition between users.

EMM Allowlisting Guidelines: Introduces instructions for configuring Shared Device environments operating in a locked-down state (such as EMM kiosk or Check-In/Check-Out with Device Guardian), which require explicit allowlisting to ensure Identity Guardian launches prior to the home screen.


New in 2.8


New Auto Logout feature automatically signs out the user after a specified period of device inactivity, starting its timer when the screen turns off from either a system timeout or a manual power button press.

UX Enhancements for Streamlined Passcode Login:



Automatic Focus and Keyboard Display - The passcode entry screen is now optimized for immediate action. The input field is automatically focused and the on-screen keyboard appears instantly, allowing users to start typing their passcode without an extra tap.

Applies to: Shared and Personally Assigned Devices during standard passcode authentication (e.g., Cloud Passcode, Admin Bypass, and primary, secondary, or fallback authentication).

Exception: This feature is not active during the initial device enrollment process.

Keyboard Action Key Submission - The passcode submission process is now more efficient. After typing, the on-screen keyboard's action key (e.g., OK, ✓, Enter) can be tapped to log in directly, eliminating the need to close the keyboard and tap a separate Submit or Unlock button on the screen.

Effortless Login with Scan-to-Submit - A new Scan-to-Submit feature provides instant login via barcode scan. Pressing the trigger to scan a passcode barcode now automatically validates the barcode and completes the login process without any further interaction.
