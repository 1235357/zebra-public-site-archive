Overview

This guide discusses the APIs provided by Identity Guardian, which uses a content provider interface to securely retrieve and share data between applications. The content provider URI is composed of four distinct parts: <Scheme:>//<Authority>/<API>/<Data>

  • Scheme - Identifies the URI accessing a content source, typically represented as: content://.
  • Authority - The name of the provider authority, usually in the form packagename.provider.
  • API - The path that differentiates the content data.
  • Data - The key that points to specific data in the path.

Example of content provider URI:   content://com.zebra.mdna.els.provider/<API>/<data>

Replace <API> and <data> with the appropriate string for specific use cases.

<queries>
    <package android:name="com.zebra.mdna.els" />

Get Lock Screen Status

(Previously known as Register for Notifications.)

Description: Provides a reliable mechanism for Line of Business (LOB) applications to query the real-time status of the Identity Guardian (IG) lock screen. Applications can query on-demand and register a ContentObserver to receive push notifications whenever the lock screen state changes.

The primary use case is to allow applications to adapt their behavior based on the device's security state, ensuring that sensitive functions are only accessible when the device is securely unlocked.

This API is only applicable when the Application Mode in Managed Configuration is set to one of the following:

  • PERSONALLY ASSIGNED
  • AUTHENTICATION
  • PROXY (with "Imprivata" or "Workspace ONE" as the "Preferred Authentication App")

If the Application Mode is not one of these, the API will return an ERROR or HIDDEN state.

Best Practices:

  • Lifecycle Management: This API should be registered in the onCreate() method and unregistered in the onDestroy() method.
  • Resiliency: The LOB app should register for the Identity Guardian content provider after installation. Following registration, Zebra recommends a 5-second delay before the initial state is queried.
  • Immediate Notifications: To receive notifications immediately, the LOB app must register to the content provider in the foreground service.

Content URI:   content://com.zebra.mdna.els.provider/lockscreenstatus/state

Response: Returns a JSON response with the lock screen state, corresponding message, and time stamp.

State Message Description & Common Triggers

Sample Code

To register for lock screen state changes (SHOWN, HIDDEN, or ERROR):

    // The ContentObserver mechanism is standard. Register an observer for the URI.
    Uri URI_CURRENT_LOCKSCREEN_STATE = Uri.parse("content://com.zebra.mdna.els.provider/lockscreenstatus/state");

    getContentResolver().registerContentObserver(URI_CURRENT_LOCKSCREEN_STATE, true, lockScreenStateContentObserver);

    private ContentObserver lockScreenStateContentObserver = new ContentObserver(mainHandler) {
        @Override
        public void onChange(boolean selfChange, @Nullable Uri uri) {
            super.onChange(selfChange, uri);
            getCurrentLockScreenState();
        }
    };

To get the current lock screen state:

Note: Zebra recommends to call the getCurrentLockScreenState() in a worker thread to query the state without blocking the main thread.

    private static String AUTHORITY = "com.zebra.mdna.els.provider";
    private static String METHOD = "lockscreenstatus/state";

    private void getCurrentLockScreenState(){

        try {
            Bundle call = getContentResolver().call(AUTHORITY, METHOD,"", null);

            if (call != null) {
                String json = call.getString("RESULT");
                JSONObject jsonObject = new JSONObject(json);
                String lockScreenState = jsonObject.getString("state");
                String message = jsonObject.getString("message");
            }
            else {
                // Handle the case where the call returns null
            }
        }
        catch (Exception e){
            // Handle exceptions appropriately
        }
    }

Get User Session

Retrieve session data associated with the current or previous user. When the device is in a locked state, these APIs are functional if the lock state is activated by specific device system events, not by an application triggering the lock state. The lock screen can be activated by the following device system events, based on Shared Device Authentication:

  • Unlocking the device (OnUnlock)
  • Rebooting the device (OnReboot)
  • Connecting the device to AC power (OnACPowerConnected)
  • Disconnecting the device from AC power (OnACPowerDisconnected)

An application can activate the lock screen by invoking Start Authentication.

Get Current User Session

Description: This API uses a content URI to retrieve data from the current user session. It accesses the cursor’s extras and extracts the result string from the extras bundle. If the result string is populated, it must be parsed into a JSON object, which is the expected output format.

When Proxy Mode is configured with either Imprivata or Workspace ONE, registered apps can automatically receive user session details during login or logout events to ensure device accountability and streamline administrative tracking. Pairing Identity Guardian with Imprivata or Workspace ONE secures shared environments, where Identity Guardian serves as a bridge, broadcast-sharing authentication event details from the third-party client directly to the registered Line of Business (LOB) apps.

  • For Imprivata: This bridge delivers details triggered by two specific events: username/password logins/logouts and NFC card tap logins/logouts. For immediate notification, Zebra recommends registering the observer within a foreground service.
  • For Workspace ONE: Identity Guardian automatically broadcasts state changes, allowing registered LOB apps acting as content observers to receive immediate callbacks with secure, logged-in or logged-out user data.

To ensure immediate notification for either integration, Zebra recommends registering the observer within a foreground service.

Note: Zebra recommends using this API instead of the Get Current User Session (Legacy) API.

Error Handling:

Expected data may not be returned to the LOB app in the following scenarios:

  • Empty Cursor: Returned if the LOB application is not authorized with MX Access Manager; refer to the Requirements section.
  • No RESULT Object: Returned if an internal error occurs in Identity Guardian during data manipulation.

Exceptions:

  • NullPointerException – Returned if the URI or method is null
  • IllegalArgumentException – Returned if the URI is not known

Known Limitations:

  • Imprivata Guest Logins: When a user unlocks the device using Imprivata with a "Guest" login, Identity Guardian does not register this as a standard login event. It does not retrieve user data or send notifications to registered applications.
    • Workaround: To detect when the device is unlocked by Imprivata under any condition (including Guest mode), applications should instead monitor the Get Lock Screen Status API.
  • Workspace ONE User Login Delay: A 10- to 25-second delay may occur during user login while waiting to receive the callback from Workspace ONE.

This sample demonstrates how to fetch current user session data from the content provider and parse it into a JSON object.

    public static final Uri URI_USER_CURRENT_SESSION_V2 = Uri.parse("content://com.zebra.mdna.els.provider/v2/currentsession");


    public void fetchCurrentUserSessionDataV2() {
        ContentResolver cr = getContentResolver(); // Get the content resolver to query the provider
        Cursor cursor = cr.query(URI_USER_CURRENT_SESSION_V2, null, null, null, null); // Query the provider using the V2 URI
        try {
            if (cursor != null) { // Check if the cursor is not null
                Log.i(TAG, "Cursor info" + cursor.getExtras()); // Log cursor information
                Bundle extras = cursor.getExtras(); // Get any extras data from the cursor
                if (extras != null) {
                    String result = extras.getString("RESULT", ""); // Retrieve the "RESULT" data from the extras
                    Log.i(TAG, "getDataForCurrentUser: key is " + result); // Log the result string

                    if (!result.isEmpty()) { // Proceed if the result is not empty
                        try {
                            JSONObject resultObject = new JSONObject(result); // Parse the result string into a JSON object
                            Log.i(TAG, "Json Result : " + resultObject.toString(1)); // Log the formatted JSON result
                        } catch (Exception e) { // Catch any exceptions during JSON parsing
                            Log.i(TAG, "Exception in parsing  " + e.getMessage()); // Log any parsing errors
                        }
                    }
                }
            }
        } catch (Exception e) { // Catch any other exceptions during the query process
            Log.e(TAG, "Exception in getDataForCurrentUser  " + e.getMessage()); // Log the exception
        } finally {
            if (cursor != null) { // Ensure that the cursor is closed to prevent memory leaks
                cursor.close();
            }
        }
    }

Retrieve Current User Session (Proxy Mode with Imprivata)

This sample demonstrates how to retrieve current user session data from the content provider and parse it into a JSON object. This applies when Proxy Mode is in use with Imprivata using the following Managed Configurations:

  • Application Mode: Proxy
  • Preferred Authentication App: Imprivata

First, register the content observer to content resolver:

    //Content provider API for current user session V2
